# Repo Review — July 2026

A housekeeping pass over the whole repository: what was cleaned up, what's
healthy, and what deserves attention next. Written for Iddo in plain language.

---

## What I cleaned up

**1. Deleted six leftover files from the repo's early days.**
`App.tsx`, `index.tsx`, `ThumbnailGenerator.tsx`, `CUTTER_SPECIFICATIONS.ts`,
`connectionRules.ts`, and `csgUtils.ts` were sitting at the top level of the
repo. These were the *original* versions of the app from before everything was
reorganized into the `src/` folder — the app has current, actively-used copies
of all of them inside `src/`. I verified three ways that nothing uses the old
ones: the page the browser loads points only at `src/`, the build's
type-checking is configured to look only at `src/`, and a text search found no
file importing them (they only imported each other). Deleting them changes
nothing about how the app runs — and if anything ever looks off, git history
keeps them forever and they can be restored in one command.

**2. Fixed documentation that still pointed at those old files.**
`SERIALIZATION_GUIDE.md` (the Grasshopper export reference) told readers to
look in the deleted files; it now points at the real locations in
`src/lib/cube/`. One similar stale pointer in `docs/internal/HANDOFF.md` was
fixed too.

**3. Brought the spec documents in line with reality.**
- `EVOLUTION_SPEC.md` described Evolution mode as a plan, but the core of it
  has long since been built and shipped. It now opens with a short status note
  saying what's built and what remains aspirational.
- `PATAPHYSICAL_V2_SPEC.md` still said Evolution was "stubbed / not yet
  implemented" and described an older tab layout. It now opens with a status
  note saying it's an April 2026 snapshot and pointing to `CONTEXT.md` for the
  current picture. The translation-pipeline content itself — the part that
  matters for the thesis — was accurate and is untouched.
- The README called the Evolution spec "unimplemented"; corrected.
- `HANDOFF.md`'s summary said the Grasshopper live-link uses WebSocket; it was
  simplified to plain HTTP a while ago, and the summary now says so. Its old
  file-tree section is also now clearly labeled as historical.

**4. Tightened `.gitignore` around environment files.**
Previously, a file named exactly `.env` (a common place to paste API keys)
would **not** have been ignored and could have been committed and pushed by
accident. Now every `.env` variant is ignored except the safe, key-free
template `.env.example`. This is purely protective — it changes nothing about
how the app runs.

None of these changes touch application code, the Firestore security rules, or
anything that runs in the browser. They are deletions of unused files and
documentation edits only.

## What's in good shape

- **The documentation system is genuinely strong.** `CONTEXT.md` is accurate —
  I cross-checked its claims (the four modes, the fitness engine's four
  sub-scores, the lexicon system, the HTTP live-link, the Firebase setup)
  against the actual code and found them all true. Very few projects keep a
  "what's actually real" document this honest.
- **Testing and CI.** Every push and pull request automatically runs the type
  checker, the unit test suite, and a real-browser end-to-end test. That's a
  real safety net for a solo project.
- **Secrets are handled correctly.** The LLM API keys live only on the server
  side, `.env.example` contains no real keys, and a scan of the repo found no
  committed secrets. (One nuance noted under "Things to watch out for".)
- **No committed build junk.** The `public/models` and `public/thumbnails`
  folders are intentional pre-computed assets, not accidents; `dist/`,
  `node_modules/`, recordings, and test artifacts are all properly ignored.
- **Internal doc links all resolve.** I checked every relative link in every
  markdown file — none are broken.

## Suggestions for the future

In priority order:

**1. Consolidate the two demo-recording scripts.** `scripts/record-demo.mjs`
and `scripts/record-demo-v2.mjs` both exist. If v2 has fully replaced v1,
delete v1; I left both because I couldn't confirm v1 is retired.
*Risk of doing it: none if v2 is what you actually use. Benefit: one less
"which one is real?" question for future sessions.*

**2. Decide the fate of the orphaned map panel.** `CONTEXT.md` itself notes
that `src/components/map/MapPanel.tsx` (the older Leaflet site picker) is no
longer mounted anywhere — it was kept as a reference for manual pinning. That's
a legitimate choice, but parked code tends to rot silently. Either revive it or
delete it (git history keeps it either way).
*Risk: none — it doesn't run today. Benefit: less dead weight to confuse a
future session into "fixing" it.*

**3. Move the hardcoded Firebase key in the meme-fetching functions into an
environment variable.** Two server functions (`api/fetch-memes.ts` and
`api/fetch-meme-by-id.ts`) contain a Firebase "web API key" written directly in
the code. Important context: this kind of key is **not a secret** — it's a
public project identifier, and Firebase security rules are what actually
protect the data. So this is not a leak. But keeping it in the code means a
key rotation would require a code change, and it reads alarmingly to anyone
scanning the repo.
*Risk of the change: low, but it touches live API code, so it should be done
deliberately and tested — which is why I documented it instead of doing it.*

**4. Add a one-page index of the documentation.** The docs are good but spread
across the root (`CONTEXT.md`, two specs, the serialization guide), `docs/`,
`docs/internal/`, `docs/demo/`, and `grasshopper/`. A short "map of the docs"
— what each file is, who it's for, and how current it is — would help future
sessions (and future Iddo) start in the right place.
*Risk: none. Benefit: faster orientation every single session.*

**5. Keep up the "Last updated" habit.** `CONTEXT.md` carries a last-updated
date and it's what made this audit easy. When a feature ships or changes shape,
a one-line touch-up there (and a date bump) is the cheapest insurance the
project has against the doc drift that this pass just cleaned up.

## Things to watch out for

Honest risk flags, none of them urgent:

- **I could not run the test suite in this environment** (dependencies weren't
  installed here). The deletions are outside the build's reach by
  configuration, so risk is minimal — but the CI run on this branch is the
  real confirmation. Check that it's green before merging.
- **The app leans on three external services** that live outside this repo:
  OpenRouter (or Anthropic) for the LLM calls, the archthesis Firebase project
  for memes/auth/projects, and the Railway-hosted map-context app for the Map
  tab. If any of those moves, changes billing, or goes down, the corresponding
  feature degrades — and no test in this repo would catch it ahead of time.
- **The Firestore security rules are the only thing protecting cloud data.**
  They currently cover projects and lexicons. Any future change to
  `firestore.rules` is security-sensitive and worth an extra-careful review,
  because a mistake there wouldn't show up as a visible bug — data would just
  be quietly exposed or blocked.
- **Some utilities are untested by design:** the thumbnail generator (the
  `?thumbnails` URL trick), the demo-recording scripts, and the snap-point
  extraction script. They're tools, not app features, so this is fine — just
  don't be surprised if one needs a small fix the next time it's used.
- **`docs/internal/HANDOFF.md` is a long historical log.** Its top "current
  state" section is maintained, but the 1,400 lines below it describe the past.
  It's clearly labeled now — treat everything below the fold as archaeology,
  not instructions.
